# ZeroTouch AI

**Show it once. Never do it again.**

A local-first document workflow project: **Teach → Learn → Execute → Verify**.
This repository currently implements **Phase 1 only**. Upload and preview documents, check local system status, and explore the application shell. Demonstration recording, workflow learning, execution, review and exports are explicitly future phases; no automation or AI extraction is claimed yet.

## Windows 11 / PowerShell quick start

Install Python 3.12 with the Windows launcher, then open PowerShell in the repository directory:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe scripts\generate_samples.py
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```

On your Windows machine, open `http://127.0.0.1:8000` in a browser. Directly invoking the venv Python avoids PowerShell activation-policy changes. In VS Code, select `.venv\Scripts\python.exe` as the interpreter. Stop the server with Ctrl+C.

### Optional local AI service

Install Ollama using its official Windows installer. The dashboard checks connectivity with a three-second timeout; the app and tests do not require it.

```powershell
ollama pull llama3.2:3b
# Only if the Ollama desktop service is not already running:
ollama serve
```

This downloads model weights and requires appropriate memory/disk resources. Phase 1 only queries `/api/tags`; it does not perform model inference.

### Configuration

`.env.example` documents available settings; files are not automatically loaded. Set process variables before launch:

```powershell
$env:OLLAMA_URL = "http://127.0.0.1:11434"
$env:OLLAMA_MODEL = "llama3.2:3b"
$env:ZEROTOUCH_DATA_DIR = Join-Path $PWD "data\runtime"
$env:ZEROTOUCH_MAX_UPLOAD_BYTES = "10485760"
```

Use a positive byte limit. The default data directory is `data/runtime` under the repository. Protect it as it contains document text and original files. Do not commit it or expose the application to a public network. The UI describes the default 10 MiB limit; API errors reflect configured custom limits.

## Try the foundation

1. Start the server and inspect Dashboard application/database and Ollama status.
2. Upload any `data/samples/invoice_*.pdf` or `invoice.txt` on Dashboard or Teach.
3. Read the extracted text preview. The original is preserved under a unique local filename.
4. Visit Workflows, Run and Results for clearly labeled upcoming-phase states.
5. Inspect `data/samples/ground_truth.json` for expected fictional values. These values are not extracted into structured fields in Phase 1.

Fixtures use obviously fictional names in three text layouts and can be regenerated byte-for-byte using the script above. Never use real invoices in public demos. Synthetic samples are intentionally shareable; runtime uploads and databases are ignored.

## API

- `GET /api/health`: database reachability and persistent counts; 503 on database failure.
- `GET /api/ollama`: availability, configured model and installed-model status; returns 200 with `available: false` when offline.
- `POST /api/documents`: multipart `file`; returns 201 with ID, name, byte size and preview text.
- `GET /api/documents/{id}`: reload a persisted document preview; 404 when missing.
- `/docs`: generated interactive API documentation.

Uploads accept text-based PDF and UTF-8 TXT only. Reject unsupported/MIME-mismatched files (415), excessive size (413), empty/corrupt/encrypted/image-only/binary files (422). PDF limit: 100 pages; extracted text limit: one million characters. No OCR. Uploaded source filenames are never used as storage paths.

## Troubleshooting

- Python not found: install Python 3.12 and verify `py -3.12 --version` in a new PowerShell window.
- Missing module: use the same venv Python for both pip installation and startup. Installation failures are not suppressed; resolve them before launching.
- Port busy: use `--port 8001` and the matching local address.
- Ollama offline: launch its desktop service; check `ollama list`, URL and model name. Preview remains usable offline.
- PDF contains no text: scanned documents need OCR, outside this phase. Use the supplied text-based fixtures.
- Invalid TXT: save as UTF-8, not UTF-16 or a renamed binary file.
- Database/storage error: confirm the configured runtime directory is writable and has free space. Do not delete originals to troubleshoot.

`app/api` HTTP boundaries; `app/core` document processing; `app/ai` Ollama adapter; `app/database.py` SQLite persistence; `app/templates` and `app/static` UI; `scripts` fixture generator; `tests` deterministic tests; `data/samples` fictional documents and ground truth; `docs` design.

See [PLAN.md](PLAN.md) for all seven milestones, [PROGRESS.md](PROGRESS.md) for actual validation and limitations, and [architecture](docs/ARCHITECTURE.md) for data and safety decisions. Windows commands are provided but native Windows execution requires verification on Windows. This single-user foundation has no authentication and should remain bound to loopback.
